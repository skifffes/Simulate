# 实验 2.2 · 阶段 3：Physical Retreat to HOME 基线

## 1. 方法

从 A 的真实终态（实验 2.1 的 40 个快照）出发，用**连续关节运动**把 Panda 送回 HOME，再启动冻结的 B/C VLA。

- **不允许瞬移**：不使用 `resetJointState` 设定退让终点；只通过 `sim.command()` 逐步发送关节目标。
- **路径**：优先直接关节空间插值（步长 0.002 rad）；如果途中出现任何机器人接触（物体、桌面、挡板、托盘、自碰撞）则回滚快照，改用"先抬升 8 cm 再回 HOME"的分段路径；两者都失败则记为该状态不可行，不做补救。
- **物体完整性**：退让期间任何机器人-物体接触都算碰撞；退让后检查物体位移 ≤5 mm、A 的原任务条件仍成立。
- **标记**：本基线使用仿真几何做碰撞检查，属于 **Oracle-Geometry Motion Planning Baseline**；这些真值不进入 VLA。
- 后继判定沿用统一协议 v2.2（首次满足且释放 → 停止动作 → 静置 1.0 s → 复核）。

## 2. 结果

| 组合 | Hard Switch（2.1 T0） | **Physical Retreat** | Oracle HOME（2.1 T1，仅参考） |
|---|---:|---:|---:|
| A90→C | 0/20 | **18/20 (90%)** | 19/20 (95%) |
| A90→B | 0/20 | **20/20 (100%)** | 17/20 (85%) |
| A0→C | 10/20 | **17/20 (85%)** | 19/20 (95%) |
| A0→B | 0/20 | **4/20 (20%)** | 1/20 (5%) |

## 3. 退让质量（80 次）

| 指标 | 结果 |
|---|---|
| 成功到达 HOME（关节误差 <0.06 rad） | **80/80** |
| 规划/执行路径 | 80/80 直接关节路径；无需分段 |
| 碰撞（物体/桌面/墙/托盘/自碰撞） | **0** |
| 物体最大位移 | **2.3×10⁻⁶ m**（数值噪声级） |
| 退让后 A 仍成功 | **80/80** |
| 退让耗时（仿真） | 829 个控制周期 ≈ **3.45 s**（20 Hz） |
| 退让耗时（墙钟） | 平均 **0.17 s** |

## 4. 失败分析

| 组合 | 失败类型 | 说明 |
|---|---|---|
| A90→C | 2 次 `final_check` | 到达托盘并释放后，1.0 s 静置复核时位置/朝向超出容差 |
| A0→C | 3 次 `timeout` | C 在 260 tick 内未完成放置 |
| A0→B | 16 次 `timeout` + 1 次 `final_check` | B 在物体 yaw≈0° 上本来就弱（原子评测 1/9），退让无法弥补 |
| A90→B | 无 | 20/20 |

A0→B 是负对照：Hard Switch 0/20 → 退让 4/20，仍远低于 A90→B 的 20/20，因为物体朝向落在 B 的困难区域。这印证了 2.1 的结论：**A0→B 主要是原子能力问题，不是交接问题**。

## 5. 对研究问题的回答

**Q3：不使用瞬移，机械臂能否从 A90 真实终态安全回到 HOME？**
能。80/80 全部成功，全部走直接关节路径，零碰撞，物体位移在数值噪声量级（2.3 μm）。

**Q4：真实回 HOME 后，A90→C 和 A90→B 能否恢复接近 Oracle HOME 的成功率？**
能。A90→C 18/20（Oracle 19/20），A90→B 20/20（Oracle 17/20，真实退让甚至略高，差异在 20 次采样的波动范围内）。

**Q5：Physical Retreat 的失败主要在哪里？**
本轮没有退让失败（0 次路径不可行、0 次碰撞、0 次物体扰动）。失败全部发生在后继 VLA：A90→C 的 2 次是放置后的稳定性复核，A0→B 的 16 次是 B 的原子短板。

**Q6：改善是否来自恢复机器人初始状态，而不是改变物体或任务条件？**
是。退让前后物体位移 <3 μm、yaw 变化 ~0（未记录到可测变化），A 的原任务条件 80/80 保持；唯一改变的是机器人关节构型，且后继任务、判据、相机与语言指令完全不变。

## 6. 结论与含义

1. **传统运动规划是一个非常强的 Baseline**：一个最简单的"关节空间回 HOME"，就把 A90→C 从 0/20 提升到 18/20、A90→B 从 0/20 提升到 20/20，与 Oracle HOME 持平。
2. 这说明实验 2 中 A90 链的组合失败**完全可以由执行层解决**，不需要新的生成式方法；任何后继可执行性引导或 Flow 方法若要立项，必须先在 A90 链上超过这个基线（目前是 90–100%）。
3. A0→C 的 17/20 vs Oracle 19/20 说明还有约 10% 的差距不是构型造成的（C 在该状态下的抓取/放置稳定性）。
4. A0→B 的 4/20 再次确认：**该组合的瓶颈是 B 的原子能力（yaw 0），不是交接**。

## 7. 局限

- 只用了 HOME 作为退让目标；没有测试"更优的启动构型"或需要绕障的复杂路径。
- 直接关节路径在 80/80 上都安全，说明这个场景的退让难度很低；换到有障碍或狭窄空间的场景，结论可能不同。
- Oracle 几何只用于碰撞检查，但真实机器人需要用视觉/深度估计；报告已标记为 Oracle-Geometry Baseline。
- 每个组合 20 次，置信区间约 ±10–13 个百分点。
- 退让目标 HOME 是训练分布的起点，这是它有效的前提；如果后继技能的合适启动构型与训练分布不同，需要另设计。
