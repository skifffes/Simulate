# 实验记录与学习要点

## 里程碑 1：看见并控制机器人

- 内容：加载 Panda、地面和固定立方体；电机执行两段平滑关节插值；GUI 显示关节角；保存画面和日志。
- API：`connect(GUI)`、`loadURDF`、`getJointStates`、`calculateInverseKinematics`、`setJointMotorControlArray`、`stepSimulation`、`getCameraImage`。
- 观察：机械臂从 HOME 缓慢移动到两个目标；关节角文字变化。
- 验证：首次预算不足已定位并修复；随后两次动作均实际到达。最终代码还检查姿态角误差、关节限位和接触。
- 与 VLA 的关系：先建立可观测、可执行、可验证的底层运动接口，并非让模型看图就能直接控制机器人。

## 里程碑 2：相同 A、不同交接状态

- 内容：A 的两个实现经过真实电机运动到同一区域，不同末端姿态留下不同关节角；直接执行 B/C，或先真实运动恢复 HOME。
- API：`getLinkState` 测量真实末端、`getJointInfo` 查询极限、`getContactPoints` 检测离散接触。
- 观察：当前 z2 的局部后继 IK 候选超限；通过公共关节构型恢复后能够到达 B/C。
- 验证：CSV 包含 A 的关节角和位姿、后继误差、失败原因及恢复成本。80 次试验成功运行，确定性重复结果一致。
- 与 VLA 的关系：展示局部控制器的起始状态依赖；还没有策略学习、语言输入、训练/测试组合划分或真实操作。

## 重要边界

1. `ik_solvable` 实际表示本次局部 IK 产生了限位内候选，不是全局可解性的数学证明；完整末端追踪另行检验。
2. 插值运动中每个物理时间步检查碰撞；没有单独的几何规划器，也没有连续碰撞或完整路径搜索证明。
3. `reached` 要求关节及末端姿态误差满足阈值；`successor_success` 还受碰撞和越界中断影响。
4. `chain_success_rate` 要求 A、可选恢复和后继均成功，避免把恢复失败后的偶然到达算整链成功。
5. 不涉及抓取、接触操作或魔方转面，立方体是静态几何参照。
6. 重复是工程复现检查，而非鲁棒性统计。种子作为复现元数据保留；目前没有随机化物理条件。
7. 失败路径可能短或零耗时，成本比较必须先看成功；不能按最短耗时选择失败控制器。
8. 公共 HOME 是关节构型，而非仅公共末端位置。仅将末端恢复同一位姿不能保证冗余机械臂具有相同交接关节状态。

## 调试历史

- Python 3.13 + pip PyBullet 无匹配包。
- 运行时安装请求 3.12 却返回 3.14，未用于执行项目。
- 项目 Conda Python 3.12 + pip PyBullet 3.2.7 仍无 Windows wheel。
- 最终 conda-forge 原生 Windows PyBullet 3.2.5 可导入且 GUI 正常。
- 首版动作预算过短；增加统一预算并补充收敛等待和实际位姿判据。
- 首版公共末端姿态恢复触发局部 IK 分支限制，改为通过电机恢复明确的 HOME 关节构型。

下一步优先加入多起点 IK 与更强路径规划作控制器对照，再预注册扰动范围和种子进行鲁棒性检查；否则不能区分物理状态困难与局部求解器缺陷。不要反复调目标直到出现想要的交叉结果后再报告为预先假设验证。
