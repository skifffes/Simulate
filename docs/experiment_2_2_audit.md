# 实验 2.2 · 阶段 1：交接协议审计

## 1. 目的

实验 2 报告 A0→C 为 **20/20**，实验 2.1 的 T0 只有 **10/20**。本轮先回答：这 10 次的差距里，有多少是**交接时机/状态**，有多少只是**评测协议**（判定窗口、判定条件）不同。

结论先行：**至少 8/20 不能用判据解释**，是真实的交接状态差异；**最多 2/20 是判定时机造成的**。因此 H0–H3 的时机实验是必要的，而且必须用统一判据重跑，不能直接比较两套历史数字。

## 4. 数据证据（A0→C）

| 指标 | 实验 2 | 2.1 T0 |
|---|---|---|
| 成功 | 20/20 | 10/20 |
| A 相位 tick | 96–102 | — |
| C 相位 tick | **41–44 即判定** | **跑满 260** |
| 成功集最终指接触 | 全部 0 | — |

2.1 T0 的 10 次失败拆开看：

- **8 次：物体从未离开 PLACE**（终态 ≈ (0.55, 0.18)）——C 根本没抓起来；
- **2 次：物体在 tick 46/47 已进入托盘**（`first_success`），但继续跑到 260 tick 后 yaw 漂到 **−15.0° / −12.9°**，超出 12° 容差，最终判失败。

这两类失败的性质不同：

- 前 8 次是**交接状态**造成的（同样的 C 策略、同样的种子，在实验 2 的即时交接下能在 42 tick 内完成）；
- 后 2 次是**判定窗口**造成的（实验 2 在 tick 42 就停止并锁定成功，根本不会看到 260 tick 时的漂移）。

## 5. 差异归因（当前证据能支持到哪一步）

- **判定协议最多解释 2/20**。如果只把实验 2 的"首次满足即停"换成 2.1 的"跑满 260 tick"，A0→C 会是 12/20，而不是 10/20。
- **其余 8/20 是交接状态差异**。但它具体是"等待 1.2 s 期间机械臂收敛/物体微动"，还是"快照构造方式"，目前不能只靠旧日志分开——这正是 H0–H3 要测的。
- 两套实验还有一处不可忽略的差异：实验 2 在 A 首次满足的**当个 tick** 就切换，而 2.1 的快照是在 A 释放并稳定 **1.2 s 之后**（相当于 H3）。所以"实验 2 = H0、2.1 = H3"是先验假设，必须用统一判据重跑验证，不能直接把 20/20 与 10/20 当作 H0/H3 的测量值。

## 6. 统一评测协议 v2.2

阶段 2 起所有实验使用同一套：

**A 的成功**：位置 ≤2 cm、yaw ≤12°、tilt ≤12°、released、lift ≥3 cm、speed <0.01 连续 3 tick。

**事件定义**：
- `t_a_success`：首次满足 A 成功；
- `t_release`：首次"无指接触且夹爪指令 ≥0.03"；
- `t_chunk_boundary`：当前动作块耗尽、下一次需要重新推理的 tick；
- `t_object_stable`：物体速度连续 5 次 <0.01。

**四个交接条件**：
- **H0**：`t_a_success` 当 tick 切换，丢弃剩余 chunk；
- **H1**：等到下一个 `t_chunk_boundary` 再切换，记录额外执行的 tick 数（必须验证 H0/H1 的动作序列确实不同）；
- **H2**：`t_release` 后 0.6 s 切换；
- **H3**：`t_release` 后 1.2 s 切换（对应 2.1 的快照时刻）。

**后继判定（统一）**：首次满足 B/C 成功条件（含 released）时停止发送新动作，保持最后命令静置 1.0 s，然后复核位置/朝向/倾角/released/速度。这样既避免"单帧锁定"，也避免"到达托盘后继续动作把成功破坏掉"。

**每次记录**：切换时刻的 7 关节 q/qd、夹爪开度与指令、末端位姿、物体位姿与速度、指接触、首块动作、等待时长、`t_a_success`/`t_release`/`t_chunk_boundary`，以及后继失败类型。

## 7. 对阶段 2/3 的直接含义

1. H0 与 H3 必须用**同一个判据**比较，否则会重犯这次 20/20 vs 10/20 的错误。
2. 预期 H0 ≈ 20/20、H3 ≈ 12/20（因为统一判据会救回 2 个瞬态）；若 H3 仍是 10/20，说明 1.2 s 等待期间确实发生了状态变化，需要在等待窗口内逐 tick 记录 q 与物体位姿来定位。
3. 物理退让 Baseline 的目标构型是 HOME，但要先确认 A 终态到 HOME 的连续路径不碰物体；这决定 T1 的 19/20 能否被真实执行复现。
4. "Best Valid Timing" 必须在**开发集**上选，再用独立种子确认；本轮不拿测试集调时机。

## 8. 尚未解决的问题（留给后续阶段）

- H0/H1 的实际物理差异有多大：H1 可能多执行最多 49 个 tick 的 A 动作，这不是纯延迟。
- 1.2 s 等待期间物体是否被夹爪残余接触拖动：需要逐 tick 记录。
- 实验 2 的 20/20 是否也包含"到托盘但未真正释放"的样本：当前 `c_done` 要求无指接触，且成功集最终接触为 0，暂未发现，但需要 H0 重跑来确认。
