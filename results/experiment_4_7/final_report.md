## 六问回答

1. **训练与在线输入是否数值一致？** 是，逐位一致（不是"在容差内"）。
2. **Anchor-16 经反归一化 + Adapter 能否还原 16 步专家目标？** 能；未触发裁剪时 1e-16 精确，
   被裁剪的 0.35% 行已单独标注（`max_delta_rad×(k+1)`）。
3. **控制器会多大程度改变动作？** 专家轨迹 0 rad / 0 次限速；跟踪误差 0.012 rad；
   模型轨迹上未观察到限速触发，但 0.012 rad 的跟踪误差在闭环中会累积。
4. **专家注入能否成功？Oracle chunk 呢？** 4/4 与 4/4；B2（原始标签重锚定）3/4。
5. **4.6 的 0.33 m 是什么？** 诊断脚本自建场景与运行时场景不一致，**不是**坐标系 bug；
   用运行时 EE 后 tick0 偏差 0.0 m，首次 >3 cm 出现在第 1–2 tick。
6. **能否宣布契约通过？** 能（除图像延迟一项 PARTIAL）。

## 关键方法

- 双路径输入对比在**模型输入张量边界**截取（训练 transforms vs `Policy._input_transform`）；
- Gate 2 用**专家标签注入**，不让模型误差干扰；
- Gate 3 四层记录（Expert/Adapter/Command/Actual），逐 tick 保存（2,828 行）；
- Gate 4 用**同一运行时 `pose()`** 重算专家 EE，避免自建 FK 场景；
- Gate 5 用匹配的 RNG split（`split(key(0))[1]`），并自查出第一版 0.19 rad 的假差异来自 RNG 不对齐。
