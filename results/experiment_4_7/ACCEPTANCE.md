## 未验证 / 局限（如实）

1. **图像延迟与 state/action 相对时刻**只用 4.6 的统计证据（`|a−s_next|`）间接证明，
   本轮**没有**逐帧检查"图像是否比 state 晚一帧"（需要重放渲染或图像-状态互相关实验）；
2. 只覆盖 4 条 episode、36 帧、707 tick；未覆盖全部 311 条；
3. Gate 5 覆盖两个 checkpoint（step3000 与 Group B step12000），但每个只有 8 个样本；
4. 安全约束在专家轨迹上 0 次触发，**不能**据此推断"安全约束对模型轨迹无影响"；
5. "首次 >3 cm 且持续的 tick" 只是阈值事件，**不是**可恢复性判据。

## 六个问题

1. **训练与在线输入是否数值一致？** 是：324/324 字段逐位一致（图像/state/prompt/token/mask 全 0 误差）。
2. **Anchor-16 经反归一化与 Adapter 能否还原 16 步专家目标？** 能：k0、k1–7 浮点精确（1e-16）；
   k8–15 在未触发裁剪时同样精确，0.35% 的行被 `max_delta_rad×(k+1)` 有意裁剪（max 0.013 rad）。
3. **控制器会多大程度改变模型输出？** 专家轨迹上 0 rad / 0 次限速；模型闭环中未见限速触发
   （4.6 trace 无 rate_limited 记录），但闭环误差 0.012 rad 的跟踪误差仍会累积。
4. **直接注入专家动作能否严格成功？Oracle chunk 呢？** 专家逐周期 **4/4**；Oracle 绝对目标 chunk **4/4**
   （Adapter 目标与专家逐位相同）；原始标签重锚定（B2）3/4（B90 ep2 因状态漂移失败，非 bug）。
5. **4.6 的 0.33 m 是什么问题？** 不是坐标系问题：`pose()` 与 FK 用的是同一 link 11（`panda_grasptarget`），
   20 个构型差 0.0 m；0.33 m 来自 4.6 诊断脚本自建场景与运行时场景不一致。改用运行时 EE 后
   tick0 偏差 0.0 m，首次 >3 cm 出现在**第 1–2 个控制周期**。
6. **能否宣布契约通过？** **能**（除"图像是否延迟一帧"标记为 PARTIAL）。
   失败层不是训练—推理—执行链路，而是**模型预测精度与闭环漂移**（主导项，见误差预算）。
