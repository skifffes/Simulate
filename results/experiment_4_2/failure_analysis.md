# 失败分析（实验 4.2 第一轮）

## 现象

| 指标 | A90（n=2） | B90（n=2） |
| --- | --- | --- |
| strict success | **0/2** | **0/2** |
| 失败原因 | `grasped_by_two_fingers` | `pushed_by_robot` |
| 机器人—方块接触步数 | **0 / 0** | **0 / 0** |
| 物体位移 | 0 | +0.0 |
| 物体终态位置 | 未动（`y=−0.006` / `0.005`） | 未动（`y=0.153` / `0.212`） |
| 推理时延 | 0.23–0.36 s/chunk | 0.23 s/chunk |
| 观测到的手臂/夹爪 | 夹爪张度 0.040 m（张开），方块未被触碰 | 同上 |

## 判定：不是"任务难"，而是**动作尺度不匹配**

1. 模型确实在控制机器人：4 条 rollout 都跑满 45 个控制周期，无 NaN、无服务器错误，
   `action_absmax`（归一化后）在 0.45–0.89，经过反归一化后相当于每步 **0.2–0.5 rad**。
2. 训练标签的物理尺度是每步 **≤0.05 rad**（`normalization_stats_check.json`：
   action Δq 的 q01/q99 ≈ −0.04/+0.05）。也就是说推理时的步幅约为训练分布的 **4–10 倍**。
3. action adapter 的 `max_delta_rad = 0.25` 把每步裁剪到 0.25 rad，
   机器人仍然每 50 ms 转动 ~14°，远超专家（每步 1–3°），因此**无法稳定接近方块**：
   - A90：机械臂摆动但没有进入抓取位姿，`robot_block_contact_steps = 0`；
   - B90：同上，方块从头到尾没有位移。
4. 训练 loss 很低（val 0.075）却物理成功率为 0，符合 prompt §12.2 描述的情形：
   **loss 与物理执行脱节**。按该节要求，先检查了动作单位、夹爪监督、chunk 时间、
   训练/执行归一化、图像字段、prompt、目标条件与裁剪情况——**唯一异常项是动作幅度**。

## 为什么幅度会偏大（三个可能原因，按证据强度排序）

1. **训练步数不足**：501 step × batch 4 = 0.79 个 epoch（`epochs_equivalent=0.795`）。
   预训练先验输出的步幅是 DROID 的 ±0.45 rad 量级，要把它压到本数据的 ±0.05 需要更多更新。
2. **归一化尺度差**：DROID 的 action q01/q99 跨 ±0.5 rad，本数据只占其中 ±0.05，
   归一化后目标值集中在 0 附近（±0.1），模型必须学会"输出接近 0"；在 MSE 上这等价于
   从 0.1 的均值附近开始，loss 很快降到 0.075，但**分布尾部仍然很宽**。
   这正是"loss 低 ≠ 行为对"的机制。
3. **推理采样步数**：flow-matching 用默认 10 步采样；若速度场尚未校准，
   大尺度误差不会被采样步数修正（这一点没有单独做消融）。

## 没有做的事（明确记录）

- 没有用测试集调整任何阈值或尺度；
- 没有对推理动作做人工缩放（那会变成"用评估集调参"）；
- 没有跑原始 `pi05_droid` 的闭环 baseline（时间预算），因此**不能**给出"微调 vs 基线"的成功率差；
- 没有重新采集数据，也没有改 4.1 的严格评价器。

## 下一步（4.2 续 / 4.3 之前）

1. 继续训练到 2–3 epoch（约 4–6k step），并每 500 step 用**验证集闭环**抽 2 条，
   观察 `action_absmax` 是否收敛到训练分布（这是比 loss 更可靠的指标）。
2. 若步数足够后幅度仍偏大，考虑"训练侧动作重标定"：把 Δq 除以训练集 std 后再进模型，
   推理侧乘回（版本化并同步写入训练/推理契约）——这属于**契约变更**，需要重训并重新验证。
3. 加一个闭环前的**离线动作分布门禁**：在固定 20 帧观测上比较模型输出与专家 Δq 的
   分位数，若偏离超过阈值就不启动闭环（省 GPU 时间）。
4. 补跑 baseline 闭环（同 seed、同场景），得到真正的配对比较。
