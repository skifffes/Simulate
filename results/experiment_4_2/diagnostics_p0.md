# 实验 4.2 P0 诊断：微调后的模型在**专家观测**上能否预测接近专家的动作？

问题：review 指出"0.027 的 loss 可能主要来自 24 维 padding"，且"动作幅度大"不一定是唯一根因。
本诊断直接在**训练/验证集的专家观测**上，比较专家动作与三个模型的**真实采样动作**，
并做 loss 归因。数据：10 帧（6 train + 4 val，每帧取 episode 的 1/3 处；A90 6 帧、B90 4 帧）。

脚本：`scripts/exp42/diagnose_actions.py`；原始数据：`/scratch/lijh/exp42/diag/action_diagnostics.json`

## 1. 动作对比（同一观测，16 步 chunk；关节单位 rad/step）

| 模型 | 幅度比（模型/专家） | 关节 MAE | 首步方向余弦 | 0.25 rad 裁剪比例 | 夹爪 MAE |
| --- | --- | --- | --- | --- | --- |
| 原始 `pi05_droid` | **4.98×** | 0.154 | 0.11 | **13.3%** | 0.406 |
| step501 | **1.54×** | 0.066 | 0.04 | 0.18% | **0.018** |
| step901 | **2.02×** | 0.061 | **−0.0001** | 1.5% | 0.034 |

逐帧示例（幅度比 / MAE / 首步余弦）：

| 帧 | baseline | step501 | step901 |
| --- | --- | --- | --- |
| A90 ep5 train f65 | 3.34 / 0.116 / 0.02 | 1.07 / 0.047 / −0.01 | 1.87 / 0.051 / −0.18 |
| A90 ep6 val f66 | 4.17 / 0.156 / 0.45 | 1.54 / 0.081 / 0.57 | 1.83 / 0.070 / 0.43 |
| A90 ep7 val f65 | 4.51 / 0.137 / 0.15 | 1.11 / 0.058 / −0.25 | 1.37 / 0.049 / **−0.78** |
| A90 ep15 val f66 | 4.48 / 0.174 / 0.23 | 1.08 / 0.080 / 0.43 | 1.11 / 0.065 / 0.28 |
| A90 ep16 val f65 | 6.46 / 0.198 / 0.52 | 1.31 / 0.067 / 0.59 | 1.66 / 0.061 / 0.68 |

## 2. Loss 归因（把真实 8 维目标置零后重算 loss）

| 模型 | 真实目标 loss | 真实维度置零 loss | 差值（真实维贡献） |
| --- | --- | --- | --- |
| step501 | 0.05727 | 0.05654 | **+0.0007** |
| step901 | 0.04032 | 0.04438 | **−0.0041** |

解读：
- 24 维 padding（目标恒为 0）占了动作维度的 **75%**，而 `pi0.compute_loss` **没有 action mask**，
  对全部 32 维求均值——这一点在 4.2 的 `training_data_contract.md` 里已记录为官方行为；
- 本次对照显示：**把真实 8 维目标置零后，loss 几乎不变（甚至更低）**。
  也就是说 0.027–0.057 这个量级的 loss **对真实动作维度几乎不敏感**，
  它主要反映"在 padding 维与噪声时间内把速度场预测到 0"；
- 因此 **不能用 loss 判断动作是否学对**。这与 review 的判断一致。

## 3. 结论（修正 4.2 报告 §6 的归因）

1. **微调确实在学**：幅度比 4.98× → 1.5–2.0×，关节 MAE 0.154 → 0.061 rad，
   夹爪 MAE 0.406 → 0.018（step501），都说明参数更新在朝正确方向走；
2. **但方向没学会**：逐帧 7 维方向余弦 ≈ 0（个别为负）。即模型学会了"步幅该多大"，
   却没学会"往哪个方向走"。闭环里 0.2–0.5 rad/step 的幅度 + 随机方向 → 机械臂扫来扫去，
   偶尔碰到方块（step901 的 69/21/22 接触步）但抓不住、推不对方向；
3. **"训得不够"不是唯一解释**：低 loss 与动作质量脱钩，继续训练把 loss 从 0.027 压到 0.01
   未必改善方向。下一步应先修 **loss 的有效维度**（按 7D/1D 分组或加 action mask）
   与**方向监督**，而不是盲目加步数；
4. **裁剪不是主因**：step501/901 的裁剪比例只有 0.18%/1.5%，baseline 才是 13.3%。
   报告里"无异常裁剪"的表述应限定为"微调模型"，原始模型确有 13% 的步被裁。
