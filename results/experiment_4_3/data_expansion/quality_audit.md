# 实验 4.3 数据扩充：质量审计

日期 2026-11-05；基准提交 `6f72bc5`；采集器 `scripts/exp41/collect41.py`（本轮新增
`--only-goals` 与 `--seed-offset`），专家/场景/严格评价器均复用 4.1 原实现，未修改任务语义。

## 1. 采集方式

| 项 | 设置 |
| --- | --- |
| 只采 train 条件 | A90 的 6 个训练目标；B90 的 4 个训练 (goal, obj, robot) 组合 |
| 入库条件 | **`strict_success=True`（`exp4.1-strict-v1.2`）且有效动作帧 ≥10**，否则只写 `records/` 供审计 |
| 种子 | `410000/420000 + gi*100 + offset + k`，offset ∈ {40, 54, 60, 40}，与原始 k<12 不相交 |
| 并行 | 4 进程（A90×2、B90×2），各自独立 `out`/`data` 目录，避免 writer 竞争 |
| 视频/相机 | 沿用 `exp4.1` 的 LeRobot v2.1 writer、v3 两路相机、20 Hz 动作 / 240 Hz 物理 |

## 6. 已知局限（未做的质量检查）

1. **没有做视频抽查**（要求"一定比例 episode 的视频与轨迹抽查"）——本轮只记录了文件数/字节，
   没有逐段看视频；图像-状态同步未独立验证（沿用 4.1 的采集路径，未改相机）。
2. **旧 90 条示范没有用 v1.2 重新严格复核**（只在上一轮用 4 条做过专家回放）。
3. **没有把新数据导出到 OpenPI 格式**，也没有重跑训练前 preflight（normalization 统计、action 契约检查），
   因此"能否直接开始训练"尚未被独立验证。
4. 重复的 9 条只做了标记与排除统计，`data/{A90,B90}` 目录仍留在服务器上（未删除）。
5. 未做"新数据 vs 旧数据"的接触阶段分布对比（需要重放接触标注），只有阶段化的粗略统计缺口。
