一句话概括
用解析式专家在 PyBullet 里采了 150 条高质量演示，微调 smolvla_base 15k 步，然后在**训练见过的种子（分布内）和全新种子（留出）**上闭环跑 80 集，中间插了 chunk50 与 n10 的执行方式对比，外面再套一个解析式专家基线 —— 目的是回答「微调后的 VLA 到底会不会抓、泛化掉多少、比专家差在哪一步」。

1. 整个流程做了 6 件事
阶段	做了什么	脚本 / 产物
① 采数据	解析式专家（IK + 状态机）驱动 Panda，随机化工件 XY/朝向/摩擦，成功才落盘，150 集	scripts/collect_atomic_vla_data.py → data/lerobot_panda_pick_place
② 修数据集	写入的 _video_stats 是 NHWC，而 LeRobot v2.1 要求 (C,1,1)，导致 LeRobotDataset 加载直接报错；按 (0,1,2) 归约后重写 episodes_stats.jsonl	scripts/repair_dataset_stats.py、server/probe_dataset.py
③ 校验	150 集 / 26 317 帧，逐集回放专家动作 vs 记录动作，3621 项检查 0 失败	scripts/validate_atomic_dataset.py → validation_150/
④ 训练	单卡 A40，15 000 步 × batch 8 = 12 万样本 = 4.56 epoch，只训动作专家，视觉塔冻结，lr 1e-4，79 分钟	server/train_smolvla.sh → checkpoints/015000
⑤ 评测	4 组 VLA（id/ood × chunk50/n10）+ 1 组专家，每组 20 集，同脚本同判据	scripts/eval_vla_policy.py → eval/*/eval.json
⑥ 附加证据	延迟基准、代表视频、loss 曲线、汇总表	bench_policy_latency.py、videos/、training/、collect_eval_table.py
三个对照轴，是这份实验设计的骨架
id vs ood：id 用训练时的种子（20261021 起），测「记住了吗」；ood 用 30000000 起的新种子，测「会泛化吗」。报告里明确写了 id 组不算泛化证据，这是最容易被人误读的地方。
chunk50 vs n10：SmolVLA 一次输出 50 步动作。chunk50 = 整块开环执行完再看一眼（1 Hz 级重规划）；n10 = 只执行前 10 步就重新推理（2 Hz 重规划）。这对应「开环轨迹准不准」与「闭环纠错值不值」的权衡。
专家基线：同一批 20 个 ood 种子跑解析式专家，100%。它给出了「这个任务本身有多难」的上界 —— 所有失败都不是环境问题。
2. 指标口径（看结果前必须知道）
成功判据（GraspPlaceTask，四条同时满足）：

工件抬升 ≥ 3 cm；
最终 XY 距目标 ≤ 2 cm；
抬升过程中滑移 ≤ 1.5 cm；
静置时关节速度收敛且夹爪已松开。
单集上限 260 个控制周期（20 Hz → 13 s 仿真时间）。

eval.json 里每条记录的关键字段：

字段	含义	怎么用
success	布尔	直接数成功率
failure	object_not_lifted / object_slipped / hand_contact	归因第一层：没抓起 / 抓了掉了 / 碰歪了
failure_stage	approach/grasp / lift/transport / place/release / completed	归因第二层：失败发生在哪一段。只有 ood n10 组细分了，其余三组记的是结算点 settle
lift_height_m	最大抬升高度	空抓的典型值 < 0.013 m，成功约 0.098 m，可以当「是否真的抓住」的硬指标
place_xy_error_m	末态工件到目标的水平距离	放置精度；空抓时是 0.17–0.22 m
ticks	用了多少个控制周期	÷20 = 仿真秒数
wall_seconds	实际墙钟耗时	含物理步进与编码，>13 s 属正常
slip_m / hand_contact_samples / release_contacts	滑移量、指尖接触采样、松爪接触	判据的中间量，排查用
inference_latency_ms_mean/p95	每集平均/尾部推理延迟	只有 n10 组有值
3. 结果怎么读
3.1 主表（80 集）
组别	成功率	失败构成
id chunk50	13/20 = 65%	空抓 6、非指尖接触 1
id n10	15/20 = 75%	空抓 4、滑落 1
ood chunk50	15/20 = 75%	空抓 3、滑落 1、接触 1
ood n10	10/20 = 50%	空抓 8、滑落 2
专家 ood	20/20 = 100%	—
读法要点：

每一行只有 20 集，95% Wilson 区间宽到 ±20 个百分点（65% 的区间是 43%–82%）。所以「id 65% vs ood 75%」这种差别没有信息量，别解读成「留出比分布内还高」。
id 组整体 65%–75%、ood 组 50%–75%，没有出现「训练集 95%、新配置 20%」那种断崖。说明 150 条轨迹确实学到了任务结构，而不是背下了某条轨迹。
n10 在 ood 上反而更差（75% → 50%），方向与 id 组相反。同种子交叉表：都成功 8、仅 chunk50 成功 7、仅 n10 成功 2、都失败 3，McNemar 精确检验 p≈0.18 —— 不显著。所以正确结论是「当前样本量测不出执行步数的优劣」，而不是「n10 更好」或「n10 更差」。
3.2 失败归因（这是全实验最有价值的部分）
合并 80 集共 27 次失败：

21 次（78%）是空抓：抬升 < 1.3 cm，末态工件几乎没动（距目标 0.17–0.22 m）。看视频会发现手臂沿一个固定方向扫过去，在空处闭合夹爪 —— 这是视觉定位 / 开环轨迹的泛化失败，不是抓取力不足。
4 次抬起 8–11 cm 后滑落（夹爪闭合时机 / 工件姿态导致接触不足）。
2 次手掌或手腕先碰到工件，把工件推走了才闭合。
结论指向很明确：瓶颈在「看到工件并把末端移到正确位置」，不在放置。 一旦抓住，后续基本能放对。

3.3 与专家对照 —— 这里有个「均值陷阱」
指标	专家	ood chunk50	ood n10
成功率	100%	75%	50%
平均抬升	0.100 m	0.089 m	0.062 m
平均放置误差	0.003 m	0.033 m	0.082 m
平均周期	176	131	133
「平均放置误差 0.082 m」看着像放置很差，其实是被 8 次空抓的 0.17–0.22 m 拉高的：

算一下就知道：10 次成功 ≈ 各 0.005 m，加上 8 个 ≈0.2 m 的空抓，(10×0.005 + 8×0.197 + 0.021 + 0.002)/20 ≈ 0.082；
只统计成功集，误差是 ≤ 0.008 m，与专家的 0.003 m 同一个量级。
同理「平均抬升 0.062 m」也是被空抓的 0.009 m 拉低的，成功集约 0.098 m。所以对比专家时要看「成功集指标」，均值差异主要反映成败比例，不反映动作质量。

周期数对比也有意思：专家用 176 个周期（8.8 s），VLA 只用 131（6.5 s）。专家更慢更保守换稳定抓取，VLA 动作更利落但抓空 —— 再次指向「定位」而非「速度」。

3.4 延迟
单次 50 步 chunk 前向：mean 288 ms、p95 355 ms；
chunk 内部取单个动作：3.5 ms；
按 n10 摊到每个周期 ≈ 32 ms，评测实测 37.9 ms。
读法：288 ms 的前向直接扛不住 20 Hz（50 ms 预算），必须靠动作块缓存把前向摊开；33–38 ms 落在预算内，但 p95 355 ms 的抖动意味着真机部署得做异步推理或降控制频率。这也解释了为什么 chunk 长度是个超参 —— 它是「开环误差」与「算力预算」之间的折中。

4. 一句话结论（可信度分级）
能学会：150 条演示足以学出完整抓取-搬运-放置，留出配置最高 75%，成功集放置误差 ≤ 1 cm。（强，80 集实测）
瓶颈在抓取前：78% 失败是空抓。（强，归因一致且视频可证）
n10 vs chunk50 优劣未定：p≈0.18。（弱，样本量不足，需每组 ≥100 集）
实时性不够：单次前向 288 ms。（强，独立基准）
没测基座模型：缺数据集统计量，所以「微调带来多少提升」没有直接对照 —— 这是最容易补、也最该补的一项。
